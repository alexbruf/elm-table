# Examples site, part 1

Fifteen TanStack React examples ported to Elm for `examples-site/`. Every
feature runs through the package: the six pipeline stages are spelled out in a
`stages` record per module (core → filtered → grouped → sorted → expanded →
paginated), and every control calls a `Table.*` transition.

## Deviations that apply to every example

1. **No "Stress Test (1M rows)" buttons.** One million rows through a pure Elm
   pipeline with no memoisation would hang the tab. "Regenerate Data" is kept
   everywhere it exists, and because a fixed seed would regenerate identical
   data, it bumps the seed (`makeData (seed + 1) …`) so the button does
   something.
2. **Row counts trimmed where TanStack uses 10,000.** `grouping`,
   `grouped-aggregation` and `aggregation` use 2,000 rows instead of 10,000;
   the pipeline is recomputed from scratch on every `update` and every `view`,
   so 10,000 made every keystroke visibly slow. 1,000 / 5,000 / `[100, 5, 3]`
   / 10 / 5 are as in the reference.
3. **No debounced inputs.** The React examples wrap their filter inputs in a
   500 ms `useDebouncedCallback`; Elm's `Browser.sandbox` has no commands, and
   filtering at these sizes is fast enough to run on every keystroke.
4. **No devtools, no `flexRender`, no "Rerender" buttons.** Cell content is
   rendered from `Table.getAllCells` / `Table.Cell.value`; the `<pre>` state
   dumps use `Shared.Controls.stateDump`.
5. **Dates print as `YYYY-MM-DD` (UTC)** rather than `toLocaleDateString`, so
   the pages are locale-independent.

## Package gaps and bugs hit

No package bugs. Three gaps worth recording:

1. **`Table.withCustomFilter` has no `autoRemove` hook.** A column filtered
   with `withCustomFilter` falls back to the default "blank" rule (`Null` and
   `""`), so a custom filter whose value is a list cannot say "an empty list
   means no filter". `filters-faceted-bucketed` needs exactly that, and the
   way out was to build the filter with `FilterFn.custom |> withResolveDataValue
   |> withAutoRemove` instead — which is also a closer port of TanStack's
   `constructFilterFn`. Input: `Value.List []` as the filter value on a
   `withCustomFilter` column keeps the (empty) filter in `State.columnFilters`
   and filters every row away.
2. **One aggregation function per column.** TanStack's
   `aggregationFn: ['count', 'mean', { id: 'range', aggregationFn: 'extent' }]`
   has no counterpart; `Table.withAggregationFn` is scalar and
   `Table.aggregationValue` / `aggregationValueOf` resolve that one function.
   Worked around in `aggregation` by folding with
   `Table.AggregationFn.aggregate` directly.
3. **No filter meta on rows (`columnFiltersMeta`).** A custom sort cannot read
   a rank the filter pass computed, so `filters-fuzzy` re-ranks inside the
   comparison and rebuilds `Config` from the current search text.

Also noted, not a package issue: `Shared.People.makeData` draws `createdAt`
with `Random.int 1262304000000 1767225600000`. `elm/random` is not uniform over
ranges wider than 2^32, and every generated date lands in a three-week window
in January–February 2010. Date columns therefore look almost constant on the
`sorting` and `filters` pages. Fixing it means changing `personGenerator`,
which is an existing function in a file shared with the other agent, so it is
left alone — a `Random.map2` over two 32-bit draws would fix it.

## Browser verification

Served `examples-site/dist` with `python3 -m http.server 8731` and drove Chrome
through the `agent-browser` skill. Clicked through, with the state dump read
back after each action:

* **basic** — renders four rows, six columns, the empty footer row.
* **sorting** — header click sorts `age` descending first (number column),
  arrow indicator appears.
* **pagination** — next / first page, go-to-page input, page size 10 → 20
  (page index re-anchored per `setPageSize`), "Show All" → `Page 1 of 1`,
  `Showing 1,000 of 1,000 Rows`.
* **filters** — text filter (749 rows), status select (267), numeric min
  (131), and the resulting `columnFilters` state.
* **filters-faceted** — datalist counts (`Search... (26)`) and filtering.
* **filters-faceted-bucketed** — ticking `Today` gives 192 rows and leaves the
  lastLogin counts alone while the storage counts drop to the filtered subset;
  `Today + Yesterday` gives 321; "Clear all filters" restores 5,000.
* **filters-fuzzy** — `frwh` in the `fullName` filter finds "Frank White" and
  switches the sort to `fullName`; `zoeper` in the global box finds
  "Zoe Perez".
* **expanding** — expand-all flattens to 210 pages of sub-rows with 🔵 leaves;
  the header checkbox selects a row and all its descendants.
* **sub-components** — the expander opens a JSON panel row under the row.
* **grouping** — grouping by status moves the column to the front, shows
  `👉 complicated (658)`, and expanding lists that group's members.
* **grouped-aggregation** — per-group median / sum / mean, and the footer
  "Grand Total 20 / 892,545 / 48.93%".
* **aggregation** — footer `filtered total 5,094,247` and
  `count: 2,000, mean: 80.07, range: 60 – 100`; the category filter and the
  row-source select both change the totals.
* **basic-external-state** — the external `setPagination` / `setSorting`
  buttons write the state dump.
* **basic-dynamic-columns** — the field checkboxes add and remove columns in
  place; the derived enum select and numeric range filters work.
* **header-groups** — all four tables, including placeholder headers and the
  row-spanning tree (screenshot checked).

No console errors or page errors on any page.

Two things could not be exercised with this tool: shift-click (the CLI has no
click modifiers — the code path is a plain `shiftKey` decoder feeding
`toggleSort { multi = True }`), and `<input type="date">` (headless Chrome
ignored both `fill` and synthetic keystrokes; the date inputs share the exact
`rangeInput` code path as the verified numeric ones).
